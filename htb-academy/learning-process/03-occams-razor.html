Occam's Razor

the principle
Concept 01 // The principle

🪒 What is Occam's Razor?

One of the central principles of modern scientific theory. Simple but nuclear:

"The most straightforward theory is preferable to all others of several sufficient possible explanations for the same state of facts. In other words: The simplest explanation is always the most probable."

Named after William of Ockham (14th century friar), the idea is: don't multiply explanations beyond necessity. If two theories explain the same evidence, go with the simpler one first.

📝 The dead computer analogy

Your computer stopped working. Here are some possibilities:

  • The power supply is faulty
  • The CPU has issues
  • The motherboard is fried
  • The power strip is switched off

Most people jump to process of elimination — they start taking the computer apart, testing each component. This already leads them in the wrong direction.

The Occam's Razor approach? Ask: "Why is the computer not getting power?" — then check the simplest thing first. Walk over to the power strip. Flip the switch. Done.

The most boring explanation was also the most probable. And it took 5 seconds instead of 5 hours.

the wrong approach
Concept 02 // The elimination trap

🚫 Process of elimination is a trap

HTB makes a critical distinction here. Most people's instinct when facing a problem is to eliminate possible causes one by one. This sounds logical. It isn't.

❌ Process of elimination

You list all possible causes, then test each one, crossing off failures.

Problem: You start with the most complex possibilities because they seem more "likely." You spend 4 hours disassembling the computer before checking if it's plugged in.

This is how most beginners troubleshoot. It's slow, exhausting, and usually wrong.

✅ Occam's Razor approach

You ask: what's the simplest possible explanation? Then test that first.

Benefit: You check the power strip in 5 seconds. If that's not it, you move to the next simplest cause. Each test takes minimal effort.

This is how experienced pentesters and sysadmins troubleshoot. Fast, efficient, methodical.

🧠 Brain Power
You're on a pentest. A web app returns a 500 error when you add a single quote to a parameter. Your colleague says "the WAF is blocking us." But what would Occam's Razor say?

Occam's Razor says: the simplest explanation is that the single quote broke a SQL query. A 500 Internal Server Error on a quote is textbook SQL injection behavior. The WAF theory is more complex (requires the WAF to be configured to return 500 specifically on quotes, which is unusual).

Test the simple theory first: try ' OR 1=1--. If it works, you just found SQLi. If it doesn't, THEN consider the WAF.

This is Occam's Razor in pentesting: don't assume exotic defenses until you've ruled out basic vulnerabilities.

🧪 Troubleshooting simulator

Apply Occam's Razor. Pick the simplest check first — not the most dramatic one.

Scenario 1: You're pentesting a web app. After running Nmap, you find port 80 (HTTP) is open but the website shows a blank page. What do you check first?
complex
🔍 The server might be using a WAF that blocks your IP — configure a VPN and try again from a different country
medium
🔧 The web server config is broken — try fuzzing for hidden directories with gobuster
simple
🌐 View the page source — maybe the HTML is there but CSS/JS isn't loading, or the page redirects with JS
Scenario 2: Your reverse shell isn't connecting back. You have RCE confirmed (you can run id via the web vuln). What's the Occam's Razor check?
medium
🛡️ The target has an egress firewall blocking outbound connections — try an ICMP tunnel or DNS exfiltration
simple
🔌 Check if your listener is actually running and on the right port — run ss -tlnp on your attack box
complex
🕵️ The target's AV/EDR is catching the reverse shell payload — rewrite it with custom obfuscation
Scenario 3: You found creds in a database dump: admin:5f4dcc3b5aa765d61d8327deb882cf99. The admin panel rejects the hash as a password. What do you do first?
complex
💻 Write a custom brute-force script that tries different hash algorithms and salting methods
simple
🔎 Google the hash — it's MD5, and 5f4dcc3b5aa765d61d8327deb882cf99 is literally "password"
medium
🧮 Set up hashcat with a massive wordlist and rule-based attack for maximum coverage
in practice
Concept 03 // In practice

🎯 Occam's Razor in practice

HTB makes a subtle but important point: using Occam's Razor sounds easier than it is. The simplest explanation isn't always correct — but it's the most probable starting point.

💡 Key nuance from HTB: "We must also distinguish between the individual details and mechanisms and the general picture or concept." In other words — understand the CONCEPT first, then worry about specific techniques.

🧩 Concepts vs. individual steps

HTB uses SQL injection as the example. Once you understand the concept of SQLi (user input gets treated as code), you can spot it anywhere — even if the specific syntax differs between MySQL, PostgreSQL, and MSSQL.

😵 Memorizing steps

"On MySQL, use UNION SELECT with information_schema.tables..."

Works until you face a PostgreSQL backend. Then you're stuck.

🧠 Understanding the concept

"User input gets concatenated into a SQL query. If I can break the query syntax, I can inject my own commands."

Works on ANY database. The syntax differs but the concept is the same.

🔑 The pentesting version

HTB's key insight for pentesting specifically:

"The simplest explanation for the best approach to penetration testing is that we work with the information we can get."

Every pentest is unique. Same systems, different configurations. You can't memorize your way through it. You gather information, form the simplest hypothesis, test it, and iterate. That's Occam's Razor applied to hacking.

📝 The "looking back" effect

HTB mentions something every pentester experiences: once you've found the solution, it always seems obvious in hindsight.

"Looking back, it always seems easy once we know the solution. The art, after all, is not to get some flag but to find the way to it."

That's because the CONCEPT was simple all along — it was the process of finding it that was hard. Occam's Razor helps you find it faster by starting with the simplest possibilities.

real world
Concept 04 // Real-world Occam's Razor

📰 When simplicity cracked the case

BUG BOUNTY

🔓 Facebook OAuth bypass (2013)

Researcher Nir Goldshlager found a way to take over ANY Facebook account. The root cause? Facebook's OAuth redirect validation could be bypassed by simply appending %23 (URL-encoded #) to the redirect URI.

Occam's Razor: before trying exotic token manipulation, he just tested if the redirect URL validation was strict. It wasn't.

INCIDENT

💀 Equifax breach (2017)

147 million SSNs leaked. Exotic zero-day? Nope. An unpatched Apache Struts server — a known CVE with a patch available for months. The simplest explanation: they just didn't update.

Occam's Razor: the biggest breach wasn't sophisticated. It was a missing patch.

CTF

🏁 Overcomplicating CTF challenges

Every CTF player has spent hours trying to reverse-engineer a binary only to realize the flag was in the HTTP response headers. Or trying to crack a hash when it was just base64 encoding.

Occam's Razor: always check the obvious stuff first. strings binary | grep flag before loading Ghidra.

SYSADMIN

🖥️ "The whole network is down!"

Classic scenario: sysadmin gets paged at 3 AM. "Everything is down!" They start checking routers, switches, DNS, DHCP... turns out someone tripped over the Ethernet cable in the server room.

Occam's Razor: check the physical layer first. Always.

🪒 What does Occam's Razor tell us?

Applied to problem-solving in cybersecurity, Occam's Razor means:
Always use the simplest tool available
Start with the simplest explanation and test that first before moving to complex theories
Complex vulnerabilities don't exist — everything is simple
Never use automated tools — manual testing is simpler

🧩 Concepts vs. steps — why does it matter?

HTB says understanding the CONCEPT is more important than memorizing individual steps because:
Individual steps are too hard to remember
Concepts are easier to write in exam answers
Every pentest is unique — concepts let you adapt to new situations, memorized steps don't
HTB wants you to skip the details and focus on theory only

🔌 The dead computer scenario

Your computer won't turn on. Applying Occam's Razor, what should you check FIRST?
Open the case and test the power supply with a multimeter
Boot from a USB to rule out OS corruption
Check if the power strip is switched on and the cable is plugged in
Replace the CMOS battery on the motherboard
