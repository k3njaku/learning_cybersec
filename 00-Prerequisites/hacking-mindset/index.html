How To Start Hacking

No, you don't need a $3,000 laptop. No, you don't need a CS degree.
You need curiosity, a browser, and about 20 minutes of your life.

"Hacking is asking 'what if?' and refusing to accept 'that's not possible.'"

Chapter 01 // The Mindset

🧠 What hacking actually is

Hollywood lied to you. Hacking isn't typing furiously in a dark room while green code rains down the screen. It's something way more interesting.

Hacking is understanding systems so deeply you can make them do things they weren't designed to do. That's it. A locksmith who knows how to open a lock without the key is "hacking" that lock. A chef who uses a technique from physics to cook a perfect egg is "hacking" the kitchen.

The Hacker's Questions 🔍

  • What does this system expect as input?
  • What happens if I give it something unexpected?
  • Who is the system trusting and why?
  • What assumptions did the developer make?

Every vulnerability in history was found by someone who asked one of these questions.

The 3 types of hackers (for real)

White Hat

🤍 Ethical Hacker

Has permission. Gets paid to find bugs before criminals do. Bug bounty hunters, pentesters, red team members. This is what you're training for.

Grey Hat

🩶 Curious Explorer

No permission, but no malicious intent. Usually discloses findings. Legal grey area — not recommended, but historically where many discoveries happened.

Black Hat

🖤 Criminal

Unauthorized access for personal gain. This is illegal everywhere. Prison time, career destroyed, FBI knocking. Not the path.

🚨 The most important rule: Only hack systems you own or have explicit written permission to test. No exceptions. The techniques here are taught in the context of legal practice environments like TryHackMe, HackTheBox, and bug bounty programs.

Chapter 02 // Your Roadmap

🗺️ The real path from zero to hacker

Here's the thing nobody tells you: there's no single path. But there IS an order that makes sense. Skip the fundamentals and you'll get stuck every time.

🗺️ Interactive Roadmap — Click a stage to see what to learn

1
Linux Basics + Networking Fundamentals
4–6 weeks · Non-negotiable foundation

You need to be comfortable with a terminal before you can hack anything. Think of it as learning to walk before you run.

# Commands you MUST know before moving on: ls -la # list files (including hidden) cd /etc # change directory cat /etc/passwd # read a file grep "root" file.txt # search in files find / -name "*.conf" 2>/dev/null # find files chmod +x script.sh # make executable sudo -l # what can I run as root? ps aux # running processes netstat -tulpn # open ports
📚 Resource: Linux Fundamentals on TryHackMe is FREE and the best starting point. Do parts 1, 2, and 3. → tryhackme.com/module/linux-fundamentals

2
How the Web Works (HTTP, DNS, Cookies)
2–3 weeks · Required for web app hacking

Every web vulnerability is just the web working in a way it wasn't supposed to. You need to understand how it's supposed to work first.

What you need to understand:

  • HTTP request/response cycle
  • GET vs POST requests
  • What are cookies & sessions?
  • How DNS resolves domain names
  • What is a web server / web app?
  • Same-Origin Policy (critical for XSS/CSRF)

Tools to install NOW:

  • 🔥 Burp Suite Community (FREE) — intercept every HTTP request
  • 🦊 Firefox + FoxyProxy extension
  • 🐧 Kali Linux (VM or WSL)
  • 🐳 Docker Desktop (for labs)

3
OWASP Top 10 — The Core Vulnerabilities
4–8 weeks · This is where the fun starts

The OWASP Top 10 is the industry's list of the most common and dangerous web vulnerabilities. Learn every single one. These are what you'll find on bug bounty programs.

A01: Broken Access Control ← IDOR, privilege escalation A02: Cryptographic Failures ← weak passwords, HTTP not HTTPS A03: Injection ← SQLi, Command injection, SSTI A04: Insecure Design ← logic flaws, business logic bugs A05: Security Misconfiguration ← open S3 buckets, default creds A06: Vulnerable Components ← outdated libraries (CVEs) A07: Auth Failures ← weak session management, JWT bugs A08: Software Integrity Failures← supply chain attacks A09: Logging Failures ← you won't find these in bounties A10: SSRF ← cloud metadata endpoint leaks

Chapter 03 // Your First Machine

💻 Set up your hacking environment — right now

Stop reading about hacking and start doing it. Here's the exact setup that gets you from zero to practicing in under an hour.

Option A: Kali Linux VM (Recommended)

Kali is a Linux distro built specifically for hacking. It comes pre-installed with 300+ security tools. You run it in a virtual machine so it's isolated from your main OS.

# Step 1: Download VirtualBox (FREE) # → https://virtualbox.org → Download VirtualBox # Step 2: Download Kali Linux VM image (pre-built, no install needed!) # → https://kali.org/get-kali → Virtual Machines → VirtualBox # Step 3: Import it # VirtualBox → File → Import Appliance → select the .ova file # Default credentials: Username: kali Password: kali # First thing to do after boot: sudo apt update && sudo apt upgrade -y
💡 RAM tip: Give the VM at least 4GB RAM and 2 CPU cores. 8GB RAM preferred. Your laptop needs at least 8GB total for this to work smoothly.

Option B: TryHackMe AttackBox (No install needed)

TryHackMe has a browser-based Kali machine called AttackBox. Free users get 1 hour/day. Premium gets unlimited. Perfect if you can't install a VM.

# Access the AttackBox: # 1. Sign up at tryhackme.com (FREE) # 2. Start any room # 3. Click "Start AttackBox" button # 4. Wait 2 minutes → full Kali Linux in your browser # No downloads. No VM. Just a browser tab.

Option C: WSL2 (Windows users)

# Open PowerShell as Administrator: wsl --install -d kali-linux # After reboot, open Kali from Start menu # First setup: sudo apt update sudo apt install -y kali-tools-web kali-tools-information-gathering # Install Burp Suite for Windows separately: # → portswigger.net/burp/communitydownload

Essential Tools — Learn These First

🔥 Burp Suite (Web Hacking #1)

A proxy that sits between your browser and the website. Every request goes through it. You can see, modify, repeat, and fuzz every single HTTP request. Absolutely essential for web app hacking.

# Free Community Edition: # portswigger.net/burp/communitydownload # Set Firefox proxy: 127.0.0.1:8080 # Install CA cert for HTTPS interception

🗺️ nmap (Reconnaissance #1)

Network scanner. Finds open ports, running services, operating systems. First thing you run on any target. "What can I even attack here?"

# Basic scan: nmap -sV -sC TARGET_IP # More aggressive (takes longer): nmap -A -p- TARGET_IP # -sV: detect service versions # -sC: run default scripts # -A: all of the above + more

🕷️ gobuster (Directory Discovery)

Brute-forces hidden directories and files on web servers. Found /admin or /backup on countless real sites. Combined with Burp, it reveals the full attack surface.

gobuster dir \ -u http://target.com \ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt \ -x php,html,txt \ -t 50

🔑 hydra (Password Attacks)

Brute-force login forms, SSH, FTP, and 50+ other protocols. Default credentials and weak passwords are still one of the most common vulnerabilities found in real engagements.

# SSH brute force: hydra -l admin -P /usr/share/wordlists/rockyou.txt \ TARGET_IP ssh # Web login form: hydra -l admin -P rockyou.txt \ TARGET_IP http-post-form \ "/login:user=^USER^&pass=^PASS^:Invalid"

Chapter 04 // Methodology

🎯 How to actually approach a target

Random clicking around a website won't find bugs. Real hackers follow a methodology. Here's the exact thought process.

🎯 The Pentesting Lifecycle — What happens in what order

Phase 1
🔍 Reconnaissance (Recon)
Collect information WITHOUT touching the target. Subdomain enumeration, WHOIS lookups, Google dorks, Shodan, LinkedIn employee research, GitHub leaks. The more you know before attacking, the more targeted your attacks are.
Phase 2
🔎 Scanning & Enumeration
Now you interact with the target. Port scanning with nmap, directory brute-forcing with gobuster, technology fingerprinting with Wappalyzer, finding hidden parameters with arjun. Map the full attack surface.
Phase 3
💥 Exploitation
Test your hypotheses. Inject SQL payloads. Try XSS in input fields. Attempt auth bypass. Fuzz parameters. Use Metasploit for known CVEs. This is the creative phase — you're an artist now.
Phase 4
🚪 Post-Exploitation
You got in. Now what? In CTFs: find the flag. In pentests: demonstrate impact (can you reach other systems? steal data?). In bug bounties: document the vuln clearly for the report.
Phase 5
📝 Reporting
Write up what you found, how you found it, and the impact. In bug bounties, a clear professional report gets paid. A vague report gets rejected. Learn to write these well.
