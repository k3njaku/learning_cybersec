UAC 🛡️

User Account Control — Windows' "Do you want to allow this app to make changes?" popup.
The last line of defense between you and a malware's dream.

"Even admins have to show their badge. Unless they know the side door." 🚪
Chapter 01 // Definition

📖 What is UAC?

User Account Control is a Windows security feature (introduced in Windows Vista, 2006) that prevents applications from making system-wide changes without explicit approval — even if you're logged in as an administrator.

📝 UAC is like the bouncer at a VIP area — even if your name is on the list (admin), you still have to show ID every time you want in

Before Vista, if you were an admin, everything you ran had admin powers. Open a browser? Admin. Run a random .exe from the internet? Admin. Malware loved this — it could do ANYTHING the moment it ran. UAC splits your admin session into two tokens: a standard one (used by default) and an elevated one (used only when you click "Yes" on the prompt). So even though you're an admin, your Firefox isn't. Your malware isn't. Unless you explicitly agree to elevate it.

The problem UAC solved

😱 Before Vista (XP era)

Most users ran as Administrator 24/7. Every program had full system access. Malware didn't need exploits — it just ran and owned everything. Drive-by downloads were devastating.

🛡️ After UAC

Admin sessions start with standard privileges. Elevation requires a consent prompt (the dimmed desktop + "Yes/No" dialog). Malware now has to either trick the user into clicking "Yes" — or find a UAC bypass.

how it works
Chapter 02 // Under the hood

⚙️ How UAC actually works

The split token model

When an admin logs into Windows, the system creates two access tokens:

  1. Standard token — used by default for all processes. Has normal user-level permissions.
  2. Elevated token — full admin rights. Only handed to a process when you approve a UAC prompt.

When an app requests elevation (e.g., an installer, system settings, cmd.exe → "Run as administrator"), Windows shows the consent prompt on a secure desktop (the dimmed screen). If you click "Yes," the process gets the elevated token.

The shield icon 🛡️

Ever notice the shield icon on certain buttons and executables in Windows? That means "clicking this will trigger UAC." It's Windows telling you: "this action needs admin approval."

🛡️ Triggers UAC

  • Installing/uninstalling software
  • Changing system settings
  • Modifying C:\Windows or C:\Program Files
  • Running "as administrator"
  • Modifying other users' files

✅ Doesn't trigger UAC

  • Running normal apps (browser, notepad)
  • Changing your own settings
  • Writing to your own user folder
  • Connecting to WiFi
  • Installing per-user apps (some)

UAC levels

Windows lets you adjust how aggressive UAC is (Settings → "Change User Account Control settings"):

🔴 Always notify

Maximum security. Prompts for EVERY elevation attempt and EVERY Windows settings change. Annoying but safest.

🟡 Default (notify for apps only)

Prompts when apps try to elevate. Doesn't prompt for Windows settings changes by admin users. The default on most installs.

🟠 Notify but don't dim desktop

Same as default but the secure desktop (dimming) is disabled. Less secure — malware can interact with the prompt window.

⚫ Never notify

UAC is effectively off. Everything runs elevated. Back to the XP days. Never do this. Please.

🚨 The built-in Administrator account (the one with RID 500) has UAC disabled by default. If you land on that account during a pentest, you're already fully elevated — no bypass needed.
bypasses
Chapter 03 // UAC bypass techniques

🥷 Getting past the bouncer without showing ID

Here's the dirty secret: Microsoft considers UAC a "convenience feature," not a security boundary. That means they won't necessarily patch UAC bypasses. There are dozens of known bypasses, and new ones pop up regularly.

How bypasses work (the pattern)

Most UAC bypasses follow the same recipe:

  1. Find a Windows binary that auto-elevates (runs elevated without prompting UAC because Microsoft trusted it)
  2. Find a way to make that binary execute YOUR code instead of (or in addition to) what it normally does
  3. Usually via registry hijacking — the binary reads a registry key to decide what to run, and your low-priv user can write to that key
CLASSIC

🎯 fodhelper.exe

A Windows binary that auto-elevates (it manages "optional features"). It reads HKCU\Software\Classes\ms-settings\Shell\Open\command before launching. Set that registry key to your payload → fodhelper runs it elevated, no UAC prompt.

# Set registry key to your payload REG ADD HKCU\Software\Classes\ms-settings\Shell\Open\command /d "cmd.exe /c powershell -e BASE64PAYLOAD" /f REG ADD HKCU\Software\Classes\ms-settings\Shell\Open\command /v DelegateExecute /t REG_SZ /f # Trigger the auto-elevating binary fodhelper.exe # Your payload runs elevated. No UAC prompt appeared.
CLASSIC

🎯 eventvwr.exe

Event Viewer auto-elevates. It reads HKCU\Software\Classes\mscfile\Shell\Open\command first (user-writable), then falls back to HKCR. Hijack the HKCU key → your command runs elevated when eventvwr launches.

MODERN

🎯 DiskCleanup / SilentCleanup

The SilentCleanup scheduled task runs with highest privileges. It executes %windir%\system32\cleanmgr.exe. By manipulating the %windir% environment variable (user-controllable), you can make it run from a writable location.

TOOL

🧰 UACME

UACME on GitHub — an open-source tool that catalogs 70+ UAC bypass methods. Each one numbered, each one documented. The pentester's UAC encyclopedia.

🧠 Brain Power

Microsoft says UAC is "not a security boundary." What does that mean for pentesters?

It means Microsoft won't patch UAC bypasses as security vulnerabilities. They're considered by-design behavior. There are dozens of known bypasses (fodhelper, eventvwr, SilentCleanup, DiskCleanup, ComputerDefaults, sdclt, and many more), and they often survive across Windows versions. For pentesters, this is great news: UAC is a speed bump, not a wall. If you're a local admin but not elevated, a UAC bypass is almost always available.

For defenders, the implication is harsh: don't rely on UAC as your only defense. Use it alongside proper least-privilege (don't give users admin), application whitelisting, and endpoint detection.

Chapter 04 // Real-world impact

📰 UAC in the wild

2017

💀 WannaCry ransomware

Exploited EternalBlue (MS17-010) for initial access, then used UAC bypass techniques to escalate and spread across networks. Once elevated: encrypt everything, demand Bitcoin. 200,000+ machines in 150 countries.

ONGOING

🔓 Commodity malware & RATs

Most modern malware families (Emotet, TrickBot, Agent Tesla) include UAC bypass modules as standard. It's so common it's practically a checkbox on the malware feature list. The fodhelper bypass alone has been seen in hundreds of malware samples.

EVERY CTF

🏁 Windows privesc rooms

Nearly every Windows CTF and pentest engagement involves UAC bypass as a step. TryHackMe, HackTheBox, OSCP — if the box is Windows and you're admin but not elevated, a UAC bypass is waiting.

2020+

🕵️ APT groups

Nation-state groups like APT29 (Cozy Bear) have been documented using UAC bypasses in their toolkits. When state-sponsored hackers use it, you know it works.

Chapter 05 // Defense & detection

🛡️ How to make UAC actually useful

  • Set UAC to "Always notify" — it's annoying, but it catches auto-elevating binary abuse.
  • Don't give users local admin — if they're standard users, UAC prompts require an admin password, not just "Yes."
  • Monitor registry keys — watch for writes to HKCU\Software\Classes\ms-settings and HKCU\Software\Classes\mscfile.
  • Application whitelisting (AppLocker / WDAC) — block unknown executables regardless of elevation.
  • EDR alerts — modern endpoint detection tools flag known UAC bypass patterns.

🎯 Quick Check

Why do most UAC bypass techniques involve Windows binaries that "auto-elevate"?
Because auto-elevating binaries have known buffer overflow vulnerabilities
Because auto-elevating binaries run with kernel-level privileges
Because they run elevated WITHOUT showing a UAC prompt — so if you can hijack what they execute, your code runs elevated silently
Because Microsoft forgot to sign these binaries
