BitLocker 🔒

Microsoft's full-disk encryption — turns your drive into an unreadable brick
for anyone who doesn't have the key. Pro & Enterprise only.

"Steal my laptop. I dare you. That SSD is a $200 paperweight without my TPM." 💪
Chapter 01 // Definition

📖 What is BitLocker?

BitLocker is a full-volume encryption feature built into Windows Pro, Enterprise, and Education editions (sorry, Home users — you get nothing). It encrypts entire drives using AES-128 or AES-256, protecting your data at rest from physical theft.

📝 BitLocker is like a safe built into your laptop — if someone steals it, they can't open the safe without the combination (TPM/password). But while you're using it, the safe door is wide open.

Imagine your hard drive is a vault full of documents. Without BitLocker, the vault door is always open — anyone who picks up the vault (steals your laptop, pulls the hard drive) can read everything. With BitLocker on, the vault is sealed with a combination lock. The combination is stored in a TPM chip soldered to your motherboard (so the drive only decrypts on THIS specific machine), or in a password/USB key you provide at boot. But here's the thing — once you type your Windows password and the machine boots up, the vault door swings open. While Windows is running and you're logged in, everything is decrypted transparently. BitLocker protects against physical theft, not against someone who catches you logged in.

💡 Edition check: BitLocker is NOT available on Windows Home. If you're on Home edition, you get "Device Encryption" (a stripped-down version that auto-enables if your hardware supports it), but you can't configure it or use advanced features. Pro, Enterprise, and Education get the full deal.
how it works
Chapter 02 // Under the hood

⚙️ How BitLocker encrypts your drive

The key chain

BitLocker uses a layered key system:

  1. FVEK (Full Volume Encryption Key) — the actual AES key that encrypts/decrypts every sector of the drive. Never leaves the disk.
  2. VMK (Volume Master Key) — encrypts the FVEK. This is what the TPM (or your password) unlocks.
  3. Key Protectors — the method used to unlock the VMK. Multiple can exist:
    • TPM only — automatic, transparent, the drive decrypts if it's in the original machine
    • TPM + PIN — you enter a PIN at boot before Windows loads
    • TPM + USB key — a USB stick must be plugged in at boot
    • Password only — for machines without TPM (less secure)
    • Recovery key — a 48-digit backup key (saved to Microsoft account, AD, or printed)

🔧 TPM (Trusted Platform Module)

A dedicated security chip on your motherboard. It stores the VMK and only releases it if the boot process hasn't been tampered with (Secure Boot integrity checks). If someone pulls your drive and puts it in another machine — the TPM isn't there, so the VMK stays locked.

🔑 Recovery key

A 48-digit numeric key generated when you enable BitLocker. This is your "break glass in emergency" key. Saved to your Microsoft account, Active Directory, Azure AD, printed on paper, or saved to a USB stick. If you lose this AND your TPM fails, your data is gone forever.

Enabling BitLocker

# GUI: Control Panel → BitLocker Drive Encryption → Turn on # PowerShell — enable on C: with TPM Enable-BitLocker -MountPoint "C:" -TpmProtector # PowerShell — enable with TPM + PIN $pin = ConvertTo-SecureString "123456" -AsPlainText -Force Enable-BitLocker -MountPoint "C:" -TpmAndPinProtector -Pin $pin # Check BitLocker status manage-bde -status C: # Get the recovery key manage-bde -protectors -get C:

Chapter 03 // BitLocker vs EFS

⚔️ Full disk vs file-level encryption

Windows has TWO built-in encryption systems on NTFS. They solve different problems:

💿 BitLocker

  • Encrypts the entire volume (every sector)
  • Protects against physical theft
  • Transparent once Windows boots — all data accessible
  • Key stored in TPM (hardware)
  • Doesn't protect files from other logged-in users
  • Pro/Enterprise only

📄 EFS (Encrypting File System)

  • Encrypts individual files/folders
  • Protects against other users on the same machine
  • Tied to user's Windows account & certificate
  • Key stored in user's profile (software)
  • Available on all NTFS volumes
  • Doesn't protect if the user is logged in (same as BitLocker)
💡 They're complementary, not competing. BitLocker stops a thief who steals your laptop. EFS stops your coworker (or another admin) from reading your files while the machine is running. Use both in a corporate environment.

Chapter 04 // The pentester & forensics angle

🥷 What BitLocker means for attackers and defenders

BLOCKED

🧱 Offline attacks are dead

Pulling the drive and mounting it on your Linux box? Nope. Booting from a USB live OS to read files? Nope. The entire volume is encrypted gibberish without the key. BitLocker is highly effective against offline attacks.

TRANSPARENT

✅ Online access is normal

If the machine is booted and the user is logged in, BitLocker is completely transparent. Every file is decrypted on-the-fly. If you have a shell on a running, unlocked Windows machine — BitLocker doesn't matter at all.

JUICY

🔑 Recovery keys in AD/Azure

In corporate environments, BitLocker recovery keys are often stored in Active Directory or Azure AD. If you compromise a domain admin account, you can pull every machine's recovery key. That's full disk access to every laptop in the org.

ADVANCED

🧊 Cold boot attacks

RAM retains data for seconds after power-off. If you can freeze the RAM chips and extract them quickly, you might recover the decryption key from memory. Extreme? Yes. Done in research? Absolutely (Princeton 2008 paper). Practical? Rarely, but it exists.

Forensics implications

  • Dead box forensics (powered off) — without the recovery key, the drive is unreadable. Period.
  • Live forensics (machine running) — capture a RAM dump. The FVEK is in memory while the volume is unlocked. Tools like volatility can extract it.
  • Hibernation file — hiberfil.sys contains a RAM snapshot. If you can get this file (from an unlocked volume), you might extract the key.
  • Memory dumps from crashes — MEMORY.DMP files can also contain the key if BitLocker was active when the crash occurred.

🧠 Brain Power

You have physical access to a powered-off laptop with BitLocker enabled. Can you read the drive?

No — not without the recovery key, TPM PIN, or the user's ability to log in. The entire drive is AES-encrypted. Pulling it out and connecting to another machine gives you encrypted gibberish. Booting from USB gives you encrypted gibberish.

But — if the laptop is running and unlocked, BitLocker is transparent. All data is accessible. The encryption only protects "data at rest" (powered off / locked). A remote shell on a booted machine bypasses BitLocker entirely.

Your options for the powered-off scenario: (1) Find the recovery key in AD/Azure AD, (2) social-engineer the user's password, (3) cold boot attack (freeze RAM, unlikely practical), or (4) accept that BitLocker did its job.

Chapter 05 // Real-world impact

📰 BitLocker in the wild

2023

💀 CVE-2023-21563 (BitLocker bypass)

Researchers demonstrated that on some systems using TPM-only authentication (no PIN), a physical attacker could downgrade the boot process to an older Windows version, extract the VMK from the TPM, and decrypt the drive. Microsoft patched it — but it showed TPM-only mode has risks. Always use TPM + PIN.

2024

🔓 TPM sniffing attacks

Security researchers showed you can physically sniff the LPC bus between the CPU and a discrete TPM chip to intercept the VMK as it's transmitted during boot. Requires physical access and hardware tools ($10-50 in parts). Integrated TPMs (fTPM inside the CPU) are immune to this — the key never leaves the chip.

EVERY CORP

🏢 Compliance requirement

HIPAA, PCI-DSS, GDPR, SOC 2 — nearly every compliance framework requires full-disk encryption on endpoints. BitLocker (or FileVault on Mac) is how most orgs check this box. A stolen unencrypted laptop = reportable breach + fines.

PENTEST

🎯 Recovery key hunting

Post-exploitation in a Windows domain: Get-ADObject -Filter {objectClass -eq 'msFVE-RecoveryInformation'} -Properties msFVE-RecoveryPassword — dumps every BitLocker recovery key stored in AD. One command, every laptop's drive unlocked.

🎯 Quick Check

You land a shell on a running, unlocked Windows machine with BitLocker enabled. Does BitLocker prevent you from reading files?
Yes — BitLocker encrypts everything, even for processes running on the machine
No — BitLocker is transparent once Windows is booted and the volume is unlocked
Only if EFS is also enabled on those specific files
Only if the user has a TPM + PIN configured
