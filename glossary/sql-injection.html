SQL Injection 💉

Sneaking SQL commands into user input so the database executes YOUR code.
The oldest web hack in the book — and still in the OWASP Top 10 after 25+ years.

"Give me a login form and a single quote, and I'll give you the entire database." ☕
Chapter 01 // Definition

📖 What is SQL Injection?

SQL Injection (SQLi) is when an attacker slips SQL commands into input fields — login forms, search bars, URL parameters — and the database blindly executes them alongside the app's own queries.

📝 The Restaurant Analogy

Imagine you're at a restaurant. You write your order on a slip of paper: "1 coffee". The waiter takes it to the kitchen.

Now imagine you write: "1 coffee; also give me everything from the safe". A dumb kitchen that reads the slip literally would hand over the coffee AND the safe contents.

That's SQLi. The "slip" is user input. The "kitchen" is the database. The semicolon is where your order ends and the attack begins.

The root cause is always the same: string concatenation. When the app builds SQL queries by gluing user input directly into the query string, the database can't tell the difference between data and commands.

-- What the developer wrote:
SELECT * FROM users WHERE username = '" + userInput + "';

-- What the attacker typed in the username field:
' OR 1=1 --

-- What the database actually executes:
SELECT * FROM users WHERE username = '' OR 1=1 --';

The ' OR 1=1 -- closes the string, adds a condition that's always true, and comments out the rest. Every row in the table comes back. Auth bypassed.

Chapter 02 // The Three Flavors

🎭 Types of SQL Injection

💬 In-Band (Classic)

The result comes back directly in the HTTP response. You see the data on the page.

UNION-based: Append a UNION SELECT to pull data from other tables into the same response.

Error-based: Force database errors that leak data in error messages.

🕵️ Blind SQLi

No data in the response — but you can infer it.

Boolean-based: Ask true/false questions. "Is the first char of the admin password > 'm'?" Page changes = yes.

Time-based: Use SLEEP(5). If the response takes 5 seconds, the condition was true.

📡 Out-of-Band (OAST)

Exfiltrate data through a side channel — DNS lookups, HTTP requests to your server.

Used when in-band and blind don't work (e.g., async queries, no visible response difference).

Chapter 03 // Impact

💥 Why SQLi is Still Devastating in 2024

🔓 Authentication Bypass

' OR 1=1 -- in a login form = instant admin access. No password needed.

📦 Data Exfiltration

Dump entire databases: usernames, passwords, credit cards, SSNs, emails. Everything.

✏️ Data Manipulation

UPDATE, INSERT, DELETE — modify prices, grant admin roles, wipe tables.

💻 Remote Code Execution

On some databases (MySQL INTO OUTFILE, MSSQL xp_cmdshell), SQLi escalates to full OS command execution.

🧠 Brain Power

If you find a blind time-based SQLi on a login page, but the app has 2FA enabled — can you still bypass authentication? Why or why not?

Think first, then click

Yes — if the SQLi is in the authentication query itself, you can make it return a valid user row without knowing the password. Whether 2FA stops you depends on WHERE the 2FA check happens. If it's a separate step AFTER the SQL query validates credentials, you'd still need to bypass 2FA. But if the app just checks "did the query return a row?" and grants a session, 2FA might never trigger.

Chapter 04 // Hall of Shame

📰 Legendary SQLi Breaches

2008

Heartland Payment Systems

SQLi led to 130 million credit/debit card numbers stolen. At the time, the largest data breach in US history. Albert Gonzalez got 20 years in prison.

2011

Sony PlayStation Network

77 million accounts compromised. Names, addresses, emails, passwords, credit cards. PSN was down for 23 days. Cost Sony an estimated $171 million.

2015

TalkTalk Telecom

A 15-year-old used SQLi to steal personal data of 157,000 customers. TalkTalk was fined £400,000 and lost 101,000 subscribers.

2019

Fortnite (Epic Games)

SQLi vulnerability in an old, forgotten Epic Games website could have been chained to steal Fortnite accounts. Reported via bug bounty before exploitation.

Chapter 06 // How to Prevent SQLi

🛡️ The Fix: Parameterized Queries

The #1 defense is parameterized queries (aka prepared statements). They separate SQL structure from data, so user input can NEVER be interpreted as SQL commands.

// ❌ VULNERABLE — string concatenation
query = "SELECT * FROM users WHERE username = '" + username + "'";

// ✅ SAFE — parameterized query (Python example)
cursor.execute("SELECT * FROM users WHERE username = %s", (username,))

Other layers of defense:

  • Input validation: Whitelist expected characters. A username shouldn't contain quotes or semicolons.
  • Least privilege: The database user the app connects with should NOT have DROP, CREATE, or FILE permissions.
  • WAF rules: Web Application Firewalls can catch common SQLi patterns — but they're bypassable and should never be your only defense.
  • ORM usage: Frameworks like Django, Rails, and Laravel use parameterized queries by default. But raw queries in ORMs are still vulnerable!
  • Error handling: Never show raw database errors to users. They leak table names, column names, and DB version info.
💡 The golden rule: NEVER trust user input. NEVER concatenate it into queries. Use parameterized queries everywhere, every time, no exceptions.

Chapter 07 // Attacker's Toolkit

🧰 SQLi Tools of the Trade

🗡️ sqlmap

The king of automated SQLi. Detects and exploits SQLi in URL params, POST data, cookies, headers. Supports 30+ database types. Can dump entire databases, read/write files, and pop shells.

sqlmap -u "http://target.com/page?id=1" --dbs

🔍 Burp Suite

Intercept requests, modify parameters, and test for SQLi manually. The Intruder tool can fuzz parameters with SQLi payloads. Scanner auto-detects SQLi.

📝 Manual Testing

Start with a single quote '. If you get a SQL error, dig deeper. Try ' OR 1=1 --, then UNION-based, then blind techniques.

📋 PayloadsAllTheThings

GitHub repo with hundreds of SQLi payloads organized by database type, bypass technique, and WAF evasion. Your cheat sheet for the field.
