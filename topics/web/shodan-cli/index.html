Chapter 01 // The Big Idea

🌐 What even IS Shodan?

Google indexes web pages (HTML content). Shodan indexes services — what ports are open, what software is running, what banners they return.

Here's how it works:

  1. Shodan crawls the entire internet 24/7
  2. It connects to every IP address on common ports (80, 443, 22, 3306, 27017, etc.)
  3. It saves the response — called a "banner"
  4. You search those banners. That's it. That's the whole product.

A "banner" is the raw text a service sends back when you connect. Like a name tag. Connect to port 80 and the server says Apache/2.4.49. Connect to port 22 and it says OpenSSH_8.2p1. Shodan saves ALL of this.

📝 The Phone Book vs. The Night Drive

Google is like a phone book — it lists businesses and their addresses. You search for "pizza near me" and get a list of pizza shops.

Shodan is like driving down every street in the world at night and writing down what you see through each window:

  • "That building has a security camera on port 554"
  • "That one has a MySQL database on port 3306"
  • "That one left their front door wide open — no password on the admin panel"
  • "That factory has an industrial control system on port 502"

Google shows you what people WANT you to see. Shodan shows you what people FORGOT to hide.

Chapter 03 // Baby's first search

🔎 Your first Shodan search

Let's search for Apache web servers. Simple. Foundational. Powerful.

# Search for "apache" in banners, limit to 5 results shodan search "apache" --limit 5
PieceWhat it does
shodanThe CLI tool
searchThe "go find stuff" command
"apache"The search term — matches against service BANNERS (not web page content)
--limit 5Only show 5 results (saves your query credits)

What the output looks like

Each result is one line with these fields:

203.0.113.42 80 Acme Corp web1.acme.com Apache/2.4.49 (Ubuntu) ...
FieldWhat it is
203.0.113.42IP address — the device's public address
80Port — which port this service runs on (80 = HTTP)
Acme CorpOrganization — who owns this IP range (ISP or company)
web1.acme.comHostname — the DNS name pointing to this IP (if any)
Apache/2.4.49...Banner — the raw response the service sent. This is the name tag.

📝 What's a "banner"?

When Shodan connects to a port, the service sends back a little greeting. This is the banner.

It's like knocking on a door and the person inside yells: "I'm Apache version 2.4.49 running on Ubuntu!"

The banner often reveals the exact software and version — which tells you exactly which CVEs to look for.

Filtering your output columns

Don't want the full wall of text? Use --fields to pick exactly which columns you see:

# Show only IP, port, organization, and hostnames shodan search "apache" --limit 5 --fields ip_str,port,org,hostnames
PieceWhat it does
--fieldsFilters the output to show only these columns
ip_strThe IP address as a string
portThe port number
orgThe organization that owns the IP
hostnamesDNS hostnames associated with the IP
💡 Pro tip: Other useful fields include location.country_name, product, version, os, vulns, and http.title.

Chapter 04 // The real power

⚡ Search Filters (where Shodan gets INSANE)

Without filters, Shodan is a flashlight. With filters, it's a laser-guided missile.

Filters go inside your search query. They narrow results to exactly what you want. Here's every filter that matters:

FilterExampleWhat it does
port:port:3306Find services on a specific port (3306 = MySQL)
country:country:PKLimit results to a country (2-letter ISO code)
city:city:LahoreLimit to a specific city
org:org:"Google"Limit to a specific organization / ISP
hostname:hostname:.gov.pkLimit to a specific domain or TLD
os:os:"Windows 7"Filter by operating system
product:product:nginxFilter by software product name
version:version:1.3.26Filter by software version number
http.title:http.title:"Dashboard"Search HTTP page titles
http.html:http.html:"wp-content"Search inside the HTML body content
ssl.cert.subject.cn:ssl.cert.subject.cn:"*.example.com"Search SSL certificate common names
ssl.cert.expired:truessl.cert.expired:trueFind services with expired SSL certs
has_screenshot:truehas_screenshot:trueOnly show results where Shodan captured a screenshot
vuln:vuln:CVE-2021-44228Find devices vulnerable to a specific CVE (paid tier only)

🔥 5 Practical Combined Filter Examples

The real magic is combining filters. Each one narrows the results further.

# 1. WordPress sites in Pakistan shodan search 'http.html:"wp-content" country:PK' --limit 20 # 2. MySQL databases in the US that responded (meaning they're exposed) shodan search 'port:3306 country:US "Access denied"' --limit 20 # 3. Dashboards WITHOUT login pages (potentially exposed!) shodan search 'http.title:"Dashboard" -http.title:"Login"' --limit 20 # 4. Apache servers with a specific VULNERABLE version shodan search 'product:Apache version:2.4.49' --limit 20 # 5. Government sites with expired SSL certs shodan search 'ssl.cert.expired:true org:"Government"' --limit 20
ExampleWhat you're finding & why it matters
#1WordPress sites in Pakistan — useful for country-scoped bug bounty or research
#2MySQL services that responded with "Access denied" — they're exposed to the internet (even if password-protected, they shouldn't be public)
#3The minus - prefix means "NOT". Dashboards without login = potentially no auth required 😱
#4Apache 2.4.49 had a critical path traversal CVE (CVE-2021-41773). Finding the exact version = finding the vuln
#5Expired SSL on government sites = easy finding for responsible disclosure programs
🧠 Brain Power
A bug bounty program says "example.com is in scope." How do you use Shodan to expand your attack surface beyond just the main website?

Three commands to map their entire footprint:

  1. shodan domain example.com — discover subdomains and DNS records
  2. shodan search hostname:example.com — find ALL services on all their hostnames (not just port 80/443)
  3. shodan search ssl.cert.subject.cn:"*.example.com" — find servers with SSL certs issued for example.com subdomains, even if DNS doesn't point to them anymore (hidden servers!)

Combined, you might find: dev servers, staging environments, forgotten APIs on weird ports, internal tools exposed by mistake, and services that moved IPs but left the old server running.

Chapter 05 // Bug bounty mode

🎯 Shodan for Bug Bounty (WordPress hunting)

You learned WordPress pentesting. Now let's use Shodan to find targets at scale.

Finding WordPress sites

# Find WordPress sites (wp-content is in every WP page's HTML) shodan search 'http.html:"wp-content"' --limit 20 --fields ip_str,hostnames,port
PieceWhat it does
http.html:"wp-content"Searches the HTML body for "wp-content" — the folder ALL WordPress sites use for themes/plugins/uploads
--fields ip_str,hostnames,portOnly show IP, hostname, and port — clean output for piping to other tools

Finding a specific vulnerable plugin

# Find sites running the Duplicator plugin (had a critical path traversal CVE) shodan search 'http.html:"wp-content/plugins/duplicator"' --limit 20

Finding WordPress login pages

# WordPress login pages — title says "Log In" and HTML has "wp-login" shodan search 'http.title:"Log In" http.html:"wp-login"' --limit 20

Country-scoped WordPress hunting

# WordPress sites in Pakistan specifically shodan search 'http.html:"wp-content" country:PK' --limit 20

The holy grail: exposed wp-config backups

# Sites accidentally serving wp-config contents (DB passwords visible!) shodan search 'http.html:"DB_PASSWORD" http.html:"wp-config"' --limit 10
SearchWhy it's powerful
http.html:"wp-content"Every WP site has this string — universal WP fingerprint
http.html:"wp-content/plugins/duplicator"Find a SPECIFIC plugin — check if its version is vulnerable
http.title:"Log In" http.html:"wp-login"Both filters must match — guarantees it's a WP login page
http.html:"DB_PASSWORD"This string is literally in wp-config.php — if it's in the HTML, someone exposed their config file
☕ Pro workflow: Find targets with Shodan → verify they're running a vulnerable plugin version with WPScan → check if it's in a bug bounty program → report responsibly → get paid.

Chapter 06 // The scary chapter

😱 Beyond WordPress — Scary stuff Shodan finds

WordPress is just the beginning. Shodan indexes the ENTIRE internet. Here's what else is out there.

🗄️ Exposed Databases

# MongoDB databases with no authentication (port 27017 is default MongoDB) shodan search "port:27017 -authentication" --limit 5 # Redis databases with no password protection shodan search "port:6379 -protected" --limit 5 # Elasticsearch instances exposed to the internet shodan search "port:9200 http.title:elasticsearch" --limit 5
PortServiceWhy it's scary
27017MongoDBDefault install = no auth. Millions of DBs were breached because of this. Entire customer databases, leaked.
6379RedisIn-memory database. If exposed = attackers can read/write data, sometimes achieve RCE via config commands
9200ElasticsearchSearch engine. Often holds logs, user data, analytics. No auth by default in older versions.

📹 IoT / Security Cameras

# WebcamXP cameras (a popular webcam software) shodan search "webcamXP" --limit 5 # Yawcam cameras shodan search "Server: yawcam" --limit 5 # DVR login pages (security camera recorders) shodan search 'http.title:"DVR Login"' --limit 5

🏭 Industrial Control Systems (SCADA)

# Modbus protocol — used in factories, power plants, water treatment shodan search "port:502 Modbus" --limit 5

Yes, actual power plants and water treatment facilities are indexed by Shodan. Many have zero authentication. This is why governments care about SCADA security.

🔧 Exposed Admin Panels

# phpMyAdmin — database management panel shodan search 'http.title:"phpMyAdmin"' --limit 5 # Grafana — monitoring dashboards (often have internal data) shodan search 'http.title:"Grafana"' --limit 5 # Jenkins — CI/CD pipelines (can lead to code execution) shodan search 'http.title:"Jenkins"' --limit 5
🚨 This needs repeating: Finding these is legal. Accessing them is NOT. Shodan shows you the unlocked doors — walking through them without permission is a crime. Even if there's no password. Even if it's "just looking." Don't do it. Use this knowledge to understand the internet's attack surface, find targets within bug bounty scope, or do responsible disclosure.
🧠 Brain Power
You run shodan search 'port:27017 -authentication' and find 50,000 MongoDB databases with no password. What ethical obligations do you have?

You cannot access the data. Period. Even though it's unprotected.

What you CAN do:

  • If you can identify the owner (via the org field or reverse DNS), you can attempt responsible disclosure — email them that their DB is exposed
  • Some researchers do mass disclosure via CERT organizations (like CERT-In for India, CERT/CC for US) who notify affected organizations in bulk
  • You can write about the general problem (without exposing specific IPs or data) to raise awareness
  • You can report it to the cloud provider (AWS, DigitalOcean, etc.) who may notify the customer

What you CANNOT do: connect to the databases, read the data, download anything, or publicly share specific IPs with exposed data.

Chapter 07 // Deep dive on a target

🔬 Host Lookup

Found an interesting IP? shodan host tells you EVERYTHING Shodan knows about it.

# Look up everything Shodan knows about an IP shodan host 8.8.8.8
PieceWhat it does
shodanThe CLI tool
hostThe "tell me about this specific IP" command
8.8.8.8The IP address to look up (this is Google's public DNS)

What you get back

The output includes:

📋 General Info

  • Organization — who owns the IP
  • ISP — the internet provider
  • Location — country, city, coordinates
  • OS — detected operating system
  • Hostnames — DNS names for this IP

🔌 Per-Port Details

  • Open ports — every port Shodan found open
  • Banners — the raw service response per port
  • Product + version — what software is running
  • SSL cert info — issuer, expiry, SANs
  • Known vulns — CVEs Shodan detected (paid)

Historical data

# See how this IP has changed over time shodan host 8.8.8.8 --history
PieceWhat it does
--historyShows historical banners — what software was running last month, last year, etc.
💡 Why history matters: A server might have been patched NOW, but last month it was running Apache 2.4.49 (vulnerable to path traversal). Historical data reveals past exposure windows — and sometimes services that were "fixed" get rolled back.
Chapter 08 // Domain recon

🌍 Domain Lookup

Know the domain but not the infrastructure? shodan domain maps it all out.

# Discover subdomains, IPs, and DNS records for a domain shodan domain example.com
PieceWhat it does
shodanThe CLI tool
domainThe "show me everything about this domain" command
example.comThe domain to investigate (no http://, no www)

What you get back

  • Subdomains — mail.example.com, dev.example.com, staging.example.com...
  • A records — which IPs each subdomain points to
  • AAAA records — IPv6 addresses
  • MX records — mail servers
  • TXT records — SPF, DKIM, verification tokens
  • CNAME records — aliases (sometimes reveal internal naming)

📝 Why this matters for bug bounty

Most bug bounty programs put *.example.com in scope. That wildcard means every subdomain is fair game.

shodan domain example.com instantly reveals subdomains you'd otherwise need tools like Subfinder or Amass to discover.

More subdomains = more attack surface = more bugs = more bounties.

Chapter 09 // The free commands

📊 Counting & Stats (zero credits used!)

These commands cost NOTHING. No search credits. Free tier? No problem. Use these all day.

Count: "How many exist?"

# How many Apache servers are on the internet right now? shodan count "apache" # How many WordPress sites in Pakistan? shodan count 'http.html:"wp-content" country:PK'
PieceWhat it does
countReturns JUST the number of matching results — no actual data, no credits used

Example output:

34,851,203

That's 34 million Apache servers. Just a number. Free. Done.

Stats: "Show me the breakdown"

# What ports do Apache servers run on? shodan stats --facets port "apache" # Where are WordPress sites? (by country) shodan stats --facets country 'http.html:"wp-content"' # What organizations run the most Nginx servers? shodan stats --facets org "product:nginx"
PieceWhat it does
statsReturns a breakdown/distribution of results — no actual result data
--facets portGroup results by port number. Other options: country, org, os, product

Example output for --facets country:

Top 10 Results US 12,453,102 DE 4,201,887 CN 3,998,451 JP 2,112,003 FR 1,876,221 ...
☕ Free tier strategy: Use count and stats to scope out your search BEFORE using search (which costs credits). Figure out how many results exist and where they're concentrated. Then spend your precious 100 credits on targeted searches.
Chapter 10 // Know thyself

🏠 Scanning your own IP

What does Shodan see when it looks at YOUR internet connection?

Find your public IP

# What's my public IP address? shodan myip
PieceWhat it does
myipOutputs your current public IP address. That's it. Simple.

Request a scan of your IP

# Ask Shodan to scan a specific IP (use YOUR own IP here) shodan scan submit 1.2.3.4
PieceWhat it does
scan submitRequests an on-demand Shodan scan of the specified IP
1.2.3.4The IP to scan (replace with YOUR IP from shodan myip)

After the scan completes (usually a few minutes), run:

# Now check what Shodan found on your IP shodan host YOUR_IP_HERE
💡 Defensive use: This is how you audit your own exposure. Is your home router exposing any services? Any development servers accidentally bound to 0.0.0.0? Run shodan myip → shodan host YOUR_IP to find out.
⚠️ Important: You can only scan IPs you own or have explicit written permission to scan. Scanning other people's IPs without permission is unauthorized network scanning — don't do it.

Shodan doesn't exist in isolation. It's the FIRST step in a multi-tool chain that ends with real bugs.

ShodanFind targets
→
httpxFilter alive
→

The actual commands, chained together

# Step 1: Find WordPress sites with Shodan, save IPs to a file shodan search 'http.html:"wp-content" country:US' --fields ip_str,port --separator : \ | tee targets.txt # Step 2: Filter for alive HTTP services with httpx cat targets.txt | httpx -silent -status-code -title | tee alive.txt # Step 3: Run Nuclei with WordPress-specific templates cat alive.txt | nuclei -tags wordpress -severity critical,high | tee vulns.txt # Step 4: Manual verification of each finding # Open each URL, verify the vuln, check if it's in a bug bounty program # Step 5: Write report, submit to the bug bounty platform
StepToolWhat it does
1ShodanFinds potential targets (IPs + ports) matching your criteria
2httpxProbes each IP:port to confirm it's actually alive and serving HTTP
3NucleiScans alive targets against a database of known vulnerability templates
4ManualYOU verify each finding is real, not a false positive, and actually exploitable
5ReportDocument the vulnerability and submit to the target's bug bounty program
💡 Important: Steps 2-5 should ONLY be run against targets you have permission to test (bug bounty programs, your own infrastructure, or targets with explicit authorization). Shodan search (step 1) is legal. Actively scanning random IPs (steps 2-3) without permission is not.
🧠 Brain Power
Why does Shodan show results for port 554 (RTSP) with has_screenshot:true? What are you actually seeing?

RTSP (Real Time Streaming Protocol) is the protocol used by security cameras for live video streaming. Port 554 is the default.

When Shodan connects to port 554 and the camera has no authentication, Shodan can capture a single frame from the video stream. That frame becomes the screenshot.

These are real security cameras whose streams are publicly accessible with no password required. There are thousands of them — office lobbies, parking lots, baby monitors, warehouse floors.

The owners either didn't know the camera was internet-accessible, or they set it up for remote viewing and forgot to set a password. Shodan just... found them.
